- (direction) Product owner asked for a SPEC.md; why-no-spec-md.md (2026-07-04) had recorded a deliberate decision not to have one. Superseded by explicit request, and that file itself names bmad-spec as the way to add one.
- (decision) Distilled from prd.md (2026-07-03) + ARCHITECTURE-SPINE.md, CORRECTED against the code as of Epic 22. The PRD predates Epics 21-22 and is stale on auth, UI, org model and distribution; where they disagree, the code wins and the divergence is logged.
- (decision) Product is PyFABRIC (Python Framework for Automated Bill of Materials & Risk Inventory in Code). Distribution stays python-inventory-supply-lens and repo stays django-python-generate-sbom (AD-21.22): product identity and distribution identity are separate.
- (capability) CAP-1 Generate a standards-based SBOM from a Python manifest (six formats in, CycloneDX JSON/XML or SPDX JSON out).
- (capability) CAP-2 Enrich it with three analysis reports — vulnerabilities, licence compliance, version currency — each degrading independently (FR-6.7).
- (capability) CAP-3 Read every report in the browser and export any of them to Excel.
- (capability) CAP-4 Watch a running job task by task, with per-task state rather than one status string (AD-20).
- (capability) CAP-5 Drive the whole thing programmatically over a versioned REST API, with an API key selecting the tenant.
- (capability) CAP-6 Attribute every job to an organization, carried into the SBOM as its supplier.
- (capability) CAP-7 Review the manifest a job was generated from.
- (capability) CAP-8 Delete a job's artifacts, or its whole record, deliberately.
- (constraint) NO AUTHENTICATION (Story 21.24). Every page and endpoint is open; identity is deferred to host-supplied OIDC (Epics 17-18). Deploy only on a trusted network. This contradicts the PRD's F1 entirely.
- (constraint) Local development must never require Docker or Podman (AD-18) — policy, not preference, in the destination organization. Enforced by a test walking the pixi run ci graph.
- (constraint) Org isolation binds the API, not the pages (AD-19, amends AD-2).
- (constraint) Server-rendered Django templates are the UI (AD-15). No SPA, no Node, no build step.
- (constraint) Blob bytes never pass between Celery phases; only keys do (AD-6). Django never streams artifact bytes; it redirects (AD-11).
- (constraint) One reusable Django app, , imported unqualified (AD-16), depending on the user MODEL REFERENCE and never a concrete User (AD-17).
- (constraint) SBOMJob.status is written only by task code (AD-12); progress is derived from JobTask rows, never reported per phase (AD-20).
- (assumption) PRD success metrics (adoption, GitHub stars) treated as out of contract — unverifiable from the system and not something downstream work derives from.
- (question) The PRD describes a dependency-GRAPH report as a fourth analysis. The shipped system has three. Was the graph dropped, or deferred?
- (question) PRD NFR-4.1 sets per-org concurrency to 5; the code enforces one job at a time per org. Which is the intent?
- (question) mark_stale_job_timed_out (FR-4.6 hard-timeout sweep) has zero callers — wire it up or delete it?
