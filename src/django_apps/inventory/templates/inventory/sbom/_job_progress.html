{% comment %} The results page's live progress fragment (Stories 21.11, 22.20). A LIST of the pipeline's tasks rather than a single "current step" line. The three analysis tasks run concurrently in a chord (AD-4), so at times two of them really are running — a sentence can only name one, which is what made the old display disagree with its own percentage. A list says what is true. Polls on the same 5s convention as the Job Status rows. A terminal job's response carries an HX-Refresh header from the view, so the page reloads into the full results view without the user touching anything — the server decides when the gate opens. The attributes are absent once the job is finished, so this fragment cannot keep polling after the work is done. The animated dots are counted by static/js/task-dots.js, which is loaded from base.html and therefore survives the 5-second swap of this fragment. `data-task-key` is how it keeps each task's count separate — a counter stored in here would restart on every swap. {% endcomment %}
